# PRD：计费 Usage 落库重构

> 版本：v1
> 日期：2026-08-26
> 状态：待评审

## 1. 背景

### 1.1 现状：所有渠道归一为 OpenAI `shared.Usage` 再落库

当前所有渠道的 adaptor `DoResponse` 返回 `*shared.Usage`（`internal/domain/shared/openai_response.go:252`），计费入口消费这个统一结构，落库的 `PromptTokens` / `CompletionTokens` 也来自此结构。

`Log` 表（`internal/store/log/log.go:21`）的 token 相关列只有两个：

```
PromptTokens     int  -- 当前语义：OpenAI 的 prompt_tokens（含 cache）
CompletionTokens int  -- 当前语义：completion_tokens
```

所有 cache 拆分（cache_read、cache_creation_5m、cache_creation_1h、audio_input、text_input 等）塞在 `Other` JSON 字段里，前端再从 JSON 反解。

### 1.2 "加加减减"发生在三处

**1. 后端计费层**（`CalculateUsage` / `PostClaudeConsumeQuota`）

因为 `PromptTokens` 的语义不统一（OpenAI 含 cache，Claude/Gemini 不含 cache），计费时需要根据 `isClaudeUsageSemantic` 判断要不要减回去：

```go
// usage.go:253
if !isClaudeUsageSemantic {
    baseTokens = baseTokens.Sub(dCacheTokens)  // OpenAI 语义：减
}
// Claude 语义：不减
```

`isClaudeUsageSemantic` 的判断（`usage.go:108`）：

```go
isClaudeUsageSemantic := relayInfo.FinalRequestRelayFormat == relayconstant.RelayFormatClaude
```

而 `FinalRequestRelayFormat` 全仓库仅 `claude/adaptor.go:130` 一处赋值。AWS 渠道复用 Claude 处理函数却不设置该标记，导致缓存计费偏差。

**2. 前端展示层**（`common-logs-columns.tsx:117`）

```ts
const input = (log.prompt_tokens || 0) - cacheRead - cacheCreation - audioInput
```

前端要从 `prompt_tokens` 里减去 `cache_tokens`、`cache_creation_tokens`、`audio_input_token_count` 才能得到"普通输入 tokens"。

**3. 归一化层**（`ClaudeUsageToOpenAIUsage` / `GeminiUsageMetadataToOpenAIUsage`）

Claude 把 `InputTokens + CacheRead + CacheCreation` 加起来当 `PromptTokens`（含 cache）；Gemini 不加 cache。两个规范归一化后 `PromptTokens` 语义不一致，下游再靠 flag 补偿。

### 1.3 TPM 的定义

TPM = 输入 + 输出，不是单纯输入：

```sql
-- log.go:637 / log.go:708
sum(prompt_tokens) + sum(completion_tokens) tpm
```

前端 i18n 也写得很清楚：

> zh: "每分钟 Token 数——最近 60 秒内...消耗的 Token 总量（输入 + 输出）"

当前 `prompt_tokens` 含 cache，所以 TPM 包含了 cache tokens。如果落库时把 `PromptTokens` 改成纯输入（不含 cache），TPM 会少算 cache 部分。本 PRD 新增 `total_processed_tokens` 列直接承载 TPM 所需的总 token，统计时直接 `sum(total_processed_tokens)`，不再拼凑多列。

## 2. 目标

在计费和落库之间加一个归一化步骤，让落库的 token 字段语义统一、自洽，消除下游的"加加减减"。

**核心原则：上游原值只读一次、只归一一次、落成唯一标准值，此后任何消费者不得再按协议加加减减、不得再靠语义标记猜。**

具体做法：

1. 新增 `Log` 表列，把 cache 拆分从 Other JSON 提升为独立列
2. 落库时 `PromptTokens` 改为纯输入（不含 cache），cache 各档独立落列
3. 计费层 `CalculateUsage` 删除 `isClaudeUsageSemantic` 分支，直接按独立列计价
4. 前端不再从 `prompt_tokens` 减法反推，直接读列
5. TPM 统计补上 cache 列

### 3.2 各字段来源说明

**PromptTokens（纯输入，不含 cache）**

- Claude Messages：`input_tokens` 字段本身不含 cache，但官方 `prompt_tokens` 语义 = `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`。本 PRD 落库时取**纯 `input_tokens`**，cache 部分独立落列。
- OpenAI Chat Completions：`prompt_tokens` **含** cache，落库时需减去 `prompt_tokens_details.cached_tokens` 得到纯输入。
- OpenAI Responses：`input_tokens` **含** cache，落库时需减去 `input_tokens_details.cached_tokens` 得到纯输入。
- Gemini：`promptTokenCount` **不含** cache（`cachedContentTokenCount` 是独立字段），直接取。

**CompletionTokens**

- Claude Messages：`output_tokens`，直接取。
- OpenAI Chat Completions：`completion_tokens`，直接取。
- OpenAI Responses：`output_tokens`，直接取。
- Gemini：`candidatesTokenCount + thoughtsTokenCount`（思考 token 计入输出）。

**CachedTokens（缓存读取）**

- Claude Messages：`cache_read_input_tokens`，独立字段。
- OpenAI Chat Completions：`prompt_tokens_details.cached_tokens`。
- OpenAI Responses：`input_tokens_details.cached_tokens`。
- Gemini：`cachedContentTokenCount`。

**WriteCachedTokens（缓存写入/创建）**

- Claude Messages：`cache_creation_input_tokens`，独立字段。另有 5m/1h 分档：`cache_creation.ephemeral_5m_input_tokens` / `cache_creation.ephemeral_1h_input_tokens`。
- OpenAI Chat Completions：无标准字段。
- OpenAI Responses：`input_tokens_details.cache_write_tokens`。
- Gemini：无标准缓存写入字段。

**AudioTokens（输入侧）**

- Claude Messages：无。
- OpenAI Chat Completions：`prompt_tokens_details.audio_tokens`。
- OpenAI Responses：无（Responses 的 `input_tokens_details` 无 audio 拆分）。
- Gemini：`promptTokensDetails[modality=audio].tokenCount`。

**ReasoningTokens（输出侧思考 token）**

- Claude Messages：无（Claude 的 thinking token 不在 usage 里单独统计，含在 `output_tokens` 中）。
- OpenAI Chat Completions：`completion_tokens_details.reasoning_tokens`。
- OpenAI Responses：`output_tokens_details.reasoning_tokens`。
- Gemini：`thoughtsTokenCount`（已计入 `CompletionTokens`）。

**ServiceTier**

- Claude Messages：请求侧 `service_tier` 字段（`ClaudeRequest.ServiceTier`），响应 usage 里无此字段。
- OpenAI Chat Completions：请求侧 `service_tier`，响应体顶层有 `service_tier` 回显。
- OpenAI Responses：请求侧 `service_tier`，响应体顶层有 `service_tier` 回显。
- Gemini：请求侧 `serviceTier`，响应无回显。

> 注：`ServiceTier` 是请求/响应顶层字段，不在 usage 结构内。当前代码在 `ClaudeRequest`（`claude.go:219`）和 `GeneralOpenAIRequest`（`openai_request.go:846`）的请求侧已有，但响应侧未解析回显值。本 PRD 暂不落库 `ServiceTier`，留作后续扩展。

**TotalProcessedTokens（TPM 用总 token）**

上游实际处理的所有 token 总和（纯输入 + 缓存读取 + 缓存写入 + 输出），用于 TPM 统计。落库后 TPM 直接 `sum(total_processed_tokens)`，不再拼凑多列。

- Claude Messages：`input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens`（官方四个字段全加）。
- OpenAI Chat Completions：`prompt_tokens + completion_tokens`（`prompt_tokens` 已含 cache，无需再加）。
- OpenAI Responses：`input_tokens + output_tokens`（`input_tokens` 已含 cache，无需再加）。
- Gemini：`promptTokenCount + toolUsePromptTokenCount + candidatesTokenCount + thoughtsTokenCount`（`promptTokenCount` 不含 cache，但 Gemini 的 `cachedContentTokenCount` 走 context/tier 分档计费，不纳入 TPM 的"处理量"口径——TPM 衡量的是上游实际处理的 token 吞吐，缓存命中部分未实际处理，不计入）。

> 注：Claude 和 OpenAI 的 cache token 是上游实际计费的处理量（缓存读取按折扣价计费、缓存写入按溢价计费），纳入 TPM；Gemini 的 `cachedContentTokenCount` 是缓存命中量（未实际处理），不纳入 TPM。各厂商口径以"上游是否对该 token 计费"为准。

### 4.2 语义变更

| 列名 | 变更前语义 | 变更后语义 |
| --- | --- | --- |
| `prompt_tokens` | OpenAI 语义（含 cache） | **纯输入**（不含 cache、不含 audio、不含 image） |
| `completion_tokens` | 不变 | 不变（含 reasoning，与上游一致） |

### 4.3 迁移策略

- 新列 `default:0`，GORM AutoMigrate 自动加列，历史记录新列全为 0。
- `prompt_tokens` 列**不回填**——历史记录保持原值（含 cache），前端/统计做兼容：新记录 `cache_tokens > 0` 时按新语义展示，旧记录 `cache_tokens == 0` 且 `prompt_tokens > 0` 时按旧语义展示（前端已有 `prompt_tokens - cache_tokens` 逻辑，旧记录减 0 等于不减，天然兼容）。
- TPM 统计改为 `sum(total_processed_tokens)`，旧记录 `total_processed_tokens` 为 0 时回退到 `sum(prompt_tokens) + sum(completion_tokens)`（兼容历史数据）

### 4.4 Other JSON 过渡

- 新列落库后，Other JSON 里的 `cache_tokens`、`cache_creation_tokens`、`cache_creation_tokens_5m`、`cache_creation_tokens_1h`、`audio_input`、`audio_output`、`text_input`、`text_output` 等 key **保留不删**，过渡期内双写（列 + JSON），前端逐步从 JSON 迁移到读列。
- 过渡期结束后（后续 PRD）清理 Other JSON 中的冗余 key。

## 5. 计费层变更

### 5.1 删除 `isClaudeUsageSemantic` 分支

`CalculateUsage`（`usage.go:246-281`）当前逻辑：

```go
if !isClaudeUsageSemantic {
    baseTokens = baseTokens.Sub(dCacheTokens)  // OpenAI 语义：减
}
```

改为：

```go
// PromptTokens 已是纯输入，不需要减
baseTokens := dPromptTokens
cachedTokensWithRatio := dCacheTokens.Mul(dCacheRatio)
dCachedCreationTokensWithRatio := dCachedCreationTokens.Mul(dCachedCreationRatio)
promptQuota := baseTokens.Add(cachedTokensWithRatio).Add(dCachedCreationTokensWithRatio)
```

`isClaudeUsageSemantic` 标记及其在 `BuildContextPricingUsage`、`PostClaudeConsumeQuota` 中的传参全部删除。

### 5.2 `PostClaudeConsumeQuota` 收敛

`PostClaudeConsumeQuota`（`quota.go:270`）当前对 OpenRouter 有特殊减法：

```go
if relayInfo.ChannelType == constant.ChannelTypeOpenRouter {
    promptTokens -= cacheTokens
    promptTokens -= cacheCreationTokens
}
```

归一化后 `PromptTokens` 已是纯输入，这段减法删除。`PostClaudeConsumeQuota` 的计费公式与 `CalculateUsage` 统一。

### 5.3 归一化函数调整

`ClaudeUsageToOpenAIUsage`（`shared/claude.go:609`）当前把 cache 加回 `PromptTokens`：

```go
promptTokens := claudeUsage.InputTokens + claudeUsage.CacheReadInputTokens + cacheCreationTokens
```

改为：

```go
// PromptTokens 只存纯输入，cache 独立保留
promptTokens := claudeUsage.InputTokens
```

`GeminiUsageMetadataToOpenAIUsage`（`billing/gemini_usage.go:23`）当前 `PromptTokens` 不含 cache，已符合新语义，无需改动。

OpenAI Chat / Responses 的归一化需要新增减法：`PromptTokens = prompt_tokens - cached_tokens`。

## 8. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 历史记录 `prompt_tokens` 语义与新记录不一致 | 前端展示、统计偏差 | 新列 `default:0`，旧记录 cache 列为 0，前端 `prompt_tokens - cache_tokens` 对旧记录减 0 等于不减，天然兼容 |
| 归一化函数改动导致计费偏差 | 直接资金影响 | 阶段 2-3 每步配对拍测试，断言新旧路径 quota 一致 |
| `ClaudeUsageToOpenAIUsage` 语义变更影响响应体 | 客户端收到的 usage 体变化 | 该函数只影响内部计费 usage，响应体 usage 另有 `OpenAIUsageToClaudeUsage` 回写路径，需同步验证 |
| TPM 公式变更影响监控 | TPM 数值跳变 | 旧记录 `total_processed_tokens` 为 0，回退到 `sum(prompt_tokens) + sum(completion_tokens)` 兼容；新记录直接用 `total_processed_tokens`，数值更准确 |
| AutoMigrate 加列失败 | 启动阻塞 | 三库验证，`default:0` 是安全加列 |

## 9. 非目标

- 不改 `ServiceTier` 落库（请求侧已有，响应侧回显值暂不落库）
- 不改 `PromptModalityTokenDetails` / `CompletionModalityTokenDetails`（Gemini 的 modality 数组，当前已展平为 `TextTokens`/`AudioTokens`/`ImageTokens`，不保留原始数组）
- 不合并 `CalculateUsage` / `PostClaudeConsumeQuota` / `PostAudioConsumeQuota` / `PostWssConsumeQuota` 四个计费入口（差异来自倍率与模态，是合理差异）
- 不改 Other JSON 的其他 key（`model_ratio`、`group_ratio`、`frt`、`speed` 等保持不变）
- 不改渠道 URL 构建、认证、路由、审计逻辑
