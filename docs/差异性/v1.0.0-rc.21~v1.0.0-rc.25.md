## 安全性

### P0

#### `0cd9dc85e` 用户资料全量回写竞态（access_token 轮换/邀请奖励原子化，安全修复合并）

涉及文件：
1. `internal/controller/user.go`（`GenerateAccessToken` :337-364）
2. `internal/model/user.go`（`User.Update` / `inviteUser`）

原因：
1. fork 的 `GenerateAccessToken` 加载整个 user 后调用 `user.Update(false)`，而 `User.Update` 用 struct 非零字段全量 `Updates` 回写，快照里的 Quota/UsedQuota/AffQuota 会覆盖并发中继扣费的结果（丢失更新窗口）。
2. `inviteUser` 同样是 load-modify-`DB.Save(user)` 全行回写。fork 无 `UpdateUserAccessToken` 定向更新函数。

应当表现为：
1. `GenerateAccessToken` 只做 `UPDATE users SET access_token=? WHERE id=?`（校验 RowsAffected）；`inviteUser` 用 `gorm.Expr` 原子自增 aff_count/aff_quota/aff_history；`UpdateSelf` 路径 Omit `access_token`、`aff_*` 等并发字段。

#### `47ba9d2c6` 充值入账守护钱包额度上限（int32 天花板防溢出）

涉及文件：
1. `internal/model/topup.go`（入账路径 :242/:473）
2. `internal/controller/topup.go`

原因：
1. fork 的 `users.quota` 列为 `type:int`（`internal/model/user.go:33`，MySQL 下 int32 上限约 21.47 亿；QuotaPerUnit=500000 时约 $4300 即溢出）。
2. fork 全库无 `MaxQuota` 上限常量、无 `ValidateTopUpQuotaCapacity`；入账是裸 `quota + ?`，无 `WHERE quota <= ?` 守护，并发回调或余额近上限时可溢出回绕成负数。

应当表现为：
1. 支付前校验「当前余额 + 本次授信 < MaxQuota」，结算用带谓词的条件 UPDATE 原子执行同一不变量，超限显式报错而非溢出。

#### `2a0ce3475` 支付前拒绝不可入账订单（额度换算上限校验）

涉及文件：

2. `internal/controller/topup_stripe.go`（`RequestAmount` :50-67 无上限校验）
3. `internal/model/topup.go`（结算换算 :222/:447-451 用截断 `int(dAmount.Mul(...).IntPart())`）

原因：

#### `ccd535ef8` 并发配额与状态更新加固（token 预扣/缓存残缺哈希/渠道状态全量回写）

涉及文件：
1. `internal/service/quota.go`（token 预扣 :540-576 为 check-then-deduct）
2. `internal/model/token_cache.go`（:30-67 裸 HINCRBY）、`internal/model/user_cache.go`（:135-145）、`internal/model/token.go`（`Update()` 全量快照回写缓存）
3. `internal/model/channel.go`（`saveStatusState` 缺失，:326-328/:861 仍 `Omit("key").Save(channel)` 全行保存；:808/:846 轮询锁未覆盖读取-落库全程）

原因：
1. token 预扣先检查快照再扣减，并发请求可同时通过检查超扣 token 额度；上游改为原子 reserve。
2. 缓存哈希缺失时生成只有 Quota 字段的残缺哈希；token 元数据更新后全量快照回写可覆盖已预扣余额。
3. 渠道状态更新用陈旧快照全行保存，会覆盖 key 之外的凭证/计数字段。
4. 注：该提交的 subscription 锁部分对 fork 不适用（fork 已删订阅模块）。

应当表现为：
1. 额度预扣为原子 reserve（Lua 守卫脚本或条件 UPDATE）；token/user 缓存只在完整哈希上增量、变更前失效；渠道状态持久化仅白名单写 status/other_info/channel_info。
