## 安全性

### P0

#### `d2f7f9ee` 限制匿名端点请求体大小，防未鉴权接口被超大 body 打爆内存

涉及文件：
1. `common/init.go`（读 env `ANONYMOUS_REQUEST_BODY_LIMIT_KB`，默认 512）
2. `constant/env.go`（新增 `AnonymousRequestBodyLimitKB`）
3. `common/request_body_limit.go`（新增）
4. `middleware/request_body_limit.go`（新增 `AnonymousRequestBodyLimit()`：`io.LimitReader` 读完，超限返回 413）
5. `router/api-router.go`（逐条挂到匿名 POST 路由）

原因：
1. fork 的匿名 POST 端点（`/setup`、`/user/register`、`/user/login`、`/user/login/2fa`、`/user/passkey/login/*`、`/user/reset`、`/oauth/email/bind`、各 webhook、`epay/notify` 等）只挂了 `CriticalRateLimit`/`TurnstileCheck`，**没有任何请求体大小限制**，Go `net/http` 默认也不限，可被超大 body 耗尽内存。
2. fork 现有的 `MaxRequestBodyMB`（128MB）只覆盖**已鉴权**的 `/v1/*` relay 路径（`GetRequestBody`），**不覆盖匿名端点**。
3. fork range 里的 `07b56f0e`（cap **上游响应体** 128MB）方向相反、作用点不同，**不是**本提交的等价物。

应当表现为：
1. 新增**独立**的匿名专用中间件（默认 512KB，env 可调，设 0 禁用），逐条挂到匿名 POST 路由；与 relay 的 128MB 上限分开，不要混用。
