title: Technical Architecture
---

NookMux is composed of a Go backend, a React admin console, and multiple persistence/cache components.

```text
Client / SDK / Console
        │
        ▼
Gin router layer (`router`)
        │
        ├─ Admin APIs: `controller` → `service` → `model` (GORM)
        │
        └─ AI relay: `middleware` → `relay` → upstream channel adapters
                                │
                                ├─ OpenAI / Azure / Anthropic / Gemini
                                ├─ OpenRouter / DeepSeek / Moonshot / Zhipu
                                ├─ AWS / Vertex / MiniMax / Ollama / SiliconFlow
                                └─ ByteDance / Xiaomi / custom channels
```

## Backend Layers

- `internal/httpapi/router/`: mounts API, relay, dashboard, static assets, and debug routes.
- `internal/httpapi/controller/`: HTTP boundary, request validation, response shaping, and audit hooks for admin actions; split into per-resource subpackages (channel, user, token, billing, relay, ...).
- `internal/httpapi/middleware/`: authentication, rate limiting, request-body restoration, dispatch, and security checks.
- `internal/domain/`: domain services: billing, channel selection and auto-disable, audit, rankings, tickets, sensitive-word matching, and group ratios.
- `internal/store/`: GORM models, migrations, cache, and database access (per-resource subpackages); must be compatible with SQLite / MySQL / PostgreSQL.
- `internal/infra/`: infrastructure: HTTP transport with SSRF protection, media decoding, token counting, notifications, payment integration, passkey, and custom voice.
- `internal/config/`: system, operations, model, billing, audit, and performance configuration.
- `internal/relay/`: AI request relay, protocol conversion, provider adaptation, usage tracking, and billing protection.
- `internal/common/`: JSON wrappers, environment variables, cache, URL/security utilities, and static asset service.

## Frontend Architecture

- `web/src/routes/`: TanStack Router file routes.
- `web/src/features/`: pages, APIs, components, hooks, and types split by feature.
- `web/src/components/`: shared UI, layout, data table, and base components.
- `web/src/i18n/`: English and Chinese frontend copy.

## Data and Cache

- Primary database defaults to SQLite, and MySQL/PostgreSQL are supported.
- Redis can be used for cache and multi-node coordination.
- Log database can be configured separately through `LOG_SQL_DSN`.
- Multimodal resources, request-body disk cache, and performance monitoring are controlled through environment variables and system settings.
