# NookMux 安全修复清单（2026-08-15 审计复核）

基于对 `nookmux-security-audit-2026-08-15.md` 的逐项复核，剔除误报、重复项与无需修复项后，确认以下问题需要修复，按优先级排列。代码位置对应 commit `ace6cd1c`。

## P0 — 下个版本必须处理

### 1. 会话 Cookie 固定 `Secure: false`

- **位置**：`main.go:146-152`
- **问题**：30 天长期会话 cookie 硬编码 `Secure: false`。HTTPS 部署若同时开放 HTTP 端口或遭降级攻击，浏览器会经明文信道发送管理员会话；`SameSite=Strict` 与 `HttpOnly` 均不能防御链路窃听。
- **修复**：按环境变量（如 `COOKIE_SECURE`）或反代探测（`X-Forwarded-Proto`）动态启用 `Secure`。

### 2. SSRF 校验 TOCTOU（DNS rebinding）

- **位置**：`common/ssrf_protection.go:303`（`net.LookupIP` 校验）与 `service/http_client.go`、`service/webhook.go:93`、`service/user_notify.go:132/226`（实际请求独立解析）
- **问题**：校验与连接两次 DNS 解析之间存在窗口，TTL=0 的权威 DNS 可使校验时返回公网 IP、连接时返回内网 IP，绕过默认私网拦截。webhook/gotify/bark URL 是普通用户可控的，触发链（relay 扣费 → 额度预警通知）普通用户即可驱动。
- **修复**：在共享 transport 上自定义 `DialContext` / `Control` hook，在连接时刻拿实际连接 IP 复查私网规则（校验与连接同 IP）。

### 3. custom_voice 上游请求完全绕过出口控制

- **位置**：`service/custom_voice.go:214-225`（`doUpstreamRequest` 裸 `http.Client`）
- **问题**：不走渠道配置的代理（违反"渠道外网请求必须走 `NewProxyHttpClient`"的项目约定）、无初始 SSRF 校验、无 redirect 复查。`/api/custom_voice/*` 为 UserAuth，普通用户可触发；恶意/被入侵的上游可用 307/308 跳转将 POST 转向任意内网端口。
- **修复**：改用 `service.GetHttpClientWithProxy(渠道代理)`，复用带 `checkRedirect` 的受控 client。

## P1 — 应尽快处理

### 4. FetchModels 裸 client 跟随 redirect 无复查

- **位置**：`controller/channel.go:1305`（`client := &http.Client{}`）
- **问题**：`validateFetchModelsURL` 只校验初始 URL，跳转后不复查，可探内网 80/443/3000/8080/8443 端口。需 Root 权限，但另一处隐患是 Anthropic 分支的 `x-api-key` 头不在 Go 跨域跳转剥离名单内，会随 redirect 外带到任意目标。
- **修复**：删除裸 client，复用 `service.GetHttpClient()`。

### 5. 支付回调过早确认

- **位置**：`controller/topup.go:261-281`（Epay）、`controller/topup_stripe.go:169-182`（Stripe）
- **问题**：Epay 在数据库入账之前就向支付平台写回 `success`；Stripe webhook 各分支入账失败仅记日志仍返回 200。瞬时数据库错误会导致"已扣款未到账"，且平台不会重试。
- **修复**：入账成功后再写 `success`；Stripe 对处理失败的分支返回 5xx 以触发平台重投。

### 6. 2FA 登录 pending session 无时效

- **位置**：`controller/user.go:86-89`（设置 `pending_user_id`）、`controller/twofa.go:351-362`（仅检查存在性）
- **问题**：登录第一阶段写入的 pending 态无时间戳校验，可随 30 天 cookie 长期存活，期间仅需通过 TOTP/备用码即可完成登录。安全验证（step-up）session 已有时效，此处漏配。
- **修复**：pending session 增加时间戳，`Verify2FALogin` 校验有效期（如 5 分钟），仿照 `SecureVerificationTimeout` 模式。

## P2 — 计划内修复

### 7. CRYPTO_SECRET 静默回落 SessionSecret

- **位置**：`common/init.go:62-65`
- **问题**：未配置 `CRYPTO_SECRET` 时静默回落，多实例部署下 `/mcp/image|video` 签名 URL 重启全失效、实例间互拒。
- **修复**：回落时打印显式启动告警；多实例部署文档要求独立配置。

### 8. 版本指纹全响应暴露

- **位置**：`middleware/cors.go:18-22`（`X-New-Api-Version` 响应头，所有请求）、`controller/misc.go:99`（`/api/status` 响应体）
- **问题**：匿名即可获取精确 commit 指纹，用于匹配该版本公开漏洞。只改 status 字段无法消除，响应头同样暴露。
- **修复**：两处一并收敛，版本信息改为仅登录/管理员可见。

### 9. 未初始化实例的 setup 抢注窗口

- **位置**：`router/api_router.go:21-22`
- **问题**：`/api/setup` 匿名可达，新部署首次暴露公网时存在 root 抢注窗口（代码内已有并发锁，防不住首次外部抢注）。
- **修复**：部署文档写明"首次初始化须在内网完成"；可选增加初始化令牌或绑定监听地址限制。

### 10. 低优先级代码质量项

- `service/custom_voice.go:592-593、626-627`：GroupId 拼接 query 未编码，含 `&`/`#` 时污染上游请求参数，改用 `url.Values`。
- `model/channel.go:362-406`（`SearchChannels`）：无 LIMIT 全量加载内存分页，渠道量大时放大内存/CPU，改 SQL 层分页。
- `controller/uptime_kuma.go:131`：`/api/uptime/status` 匿名可触发服务端内网请求（≤40 个/次），考虑加登录态或结果缓存。
